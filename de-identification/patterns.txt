# De-identification regex patterns: one Python regex per line, for the
# categories that are SHAPES rather than fixed literals. '#' starts a
# comment. Patterns are compiled case-sensitively (as written) so token
# shapes stay exact; add inline (?i) if you want a specific line to ignore
# case. Keep one pattern per line.

# --- Incident / work-order / session ids ---------------------------------
# fleet issue references like fleet#399
fleet#\d+
# work orders like wo-abc123. Left \b so it does not match inside a normal
# word such as "two-verb" (the 't' before "wo" blocks the boundary).
\bwo-[a-z0-9-]+
# build-supervisor session ids like bs-patterns-repo-0825
\bbs-[a-z0-9-]+-\d{4}\b
# cockpit session ids like cockpit-a1b2c3
cockpit-[a-z0-9]+
# Note: "PR #123" / "PR#123" is NOT sensitive and is intentionally NOT listed.

# --- Contract numbers (best effort) --------------------------------------
# A leading 'C' plus 5+ digits, e.g. C12345. Best effort: may over-match a
# bare code that happens to look like this. Tune per client if noisy.
\bC\d{5,}\b
# PO / SOW / MSA order numbers, e.g. SOW-1207, PO 4412, MSA-100
\b(?:PO|SOW|MSA)[- ]?\d{3,}\b

# --- Secrets / tokens -----------------------------------------------------
# Vendor-specific token shapes are matched directly (high confidence):
sk-[A-Za-z0-9]{16,}
ghp_[A-Za-z0-9]{20,}
AKIA[0-9A-Z]{12,}
xox[baprs]-[A-Za-z0-9-]{10,}
# Generic high-entropy value, keyed on an obvious secret context word on the
# SAME token so ordinary long words do not trip. Tradeoff: a secret assigned
# far from its keyword, or with an unusual separator, can slip past here; the
# vendor shapes above and the denylist are the backstops.
(?i)(?:secret|token|passwd|password|api[_-]?key|bearer)['"\s:=]+[A-Za-z0-9_\-\.]{24,}

# --- Redis URLs -----------------------------------------------------------
rediss?://\S+
